# llm2sql 0.3.0 (2026-08-25)

제품 버전 **0.3.0**. Python 패키지명은 `llm2sql`을 유지하고, GitHub 원격 저장소 이름은 `txt2sql`이다.

SQP Plan 스키마는 v1.1, `SEMANTIC_PLAN_MODE` 기본값은 `hybrid`이다.

---

## 1. 질의 엔진 — 업로드 레이어를 자동으로 찾음

이전에는 RAG가 `_SEARCHABLE_FQNAMES` 고정 목록만 봤다. `adm_urban_area_per_capita`(활동인구 1인당 시가화용지 …)처럼 새로 올린 공간 테이블은 임베딩이 있어도 검색 대상이 아니었다.

- `schema_retriever.searchable_fqnames(conn)`이 `geometry_columns`·정보스키마에서 공간 테이블을 발견한다. `pnu_def`와 구별 최신 `AL_D198_*`를 포함한다. `temp_*`·시스템 테이블은 제외한다.
- 같은 DB 연결에서 20초 동안 목록을 재사용한다.
- `table_metadata` 표시명·설명·분류에서 동의어를 뽑는다. 질문에 **시가화용지**처럼 고유 토큰이 있으면 해당 테이블을 RAG 후보 앞에 둔다.
- 업로드·메타데이터 저장 때 `sync_dataset_after_change`가 해당 테이블 스키마를 다시 임베딩한다.

건물 건폐율·연면적 같은 SQP 경로는 여전히 D010/D198 허용 테이블만 쓴다. 시가화용지 전용 질문은 RAG(일반 LLM SQL)로 간다.

## 2. 지명 사전 자동 갱신

`gazetteer_data.json`은 `pnu_def`와 `BND_ADM_DONG_PG`에서 만든다. 전국 시도·시군구·법정동·행정동을 쓴다.

갱신 기점은 둘이다. 둘 다 `sync_dataset_after_change`를 탄다.

| 기점 | 동작 |
|------|------|
| Shapefile 업로드 | 코드가 있으면 메타 자동 채움 → 스키마 임베딩 → D198 구 맵 → 지명 사전 |
| 메타데이터 저장(화면·CSV) | 표시명 반영 후 임베딩 재생성 → D198 구 맵 → 지명 사전 |

내용이 이전 JSON과 같으면 파일을 다시 쓰지 않는다. 수동 실행은 `python scripts/build_gazetteer.py`.

## 3. 지도 — 구간별 색상 (단계구분도)

출력 레이어 오른쪽 클릭 → **구간별 색상...**.

- 분류: 자연구간(Jenks), 등간격, 분위수, 사용자 정의. 구간 3–9.
- 색상표: Blues, Greens, Oranges, Reds, Purples, Viridis, YlOrRd.
- NULL은 0으로 치지 않고 `#BDBDBD` / 데이터 없음.
- 적용 시 GeoServer `choropleth__*` named style. WMS는 `STYLES`, WFS는 같은 분류 JSON.
- 코드·ID 열(`sgis_cd` 등)은 기본 선택에서 뒤로 보낸다. 지표 열을 먼저 고른다.

API: `/api/map/choropleth/fields|stats|classify|preview|apply|reset`. 사용 설명은 `docs/map_choropleth.md`.

## 4. 속성 테이블 LLM 설명

`/api/map/explain`은 열 개수 상한을 넘기면 422로 거절하지 않고 앞부분만 잘라 설명을 요청한다. 시가화용지 레이어처럼 열이 66개인 경우에도 Ollama가 호출되고 설명 창이 뜬다. 표 자체는 전체 열을 보여 준다.

## 5. 데이터 관리 CSV

`/data/metadata`에서 테이블·컬럼 메타데이터를 UTF-8-SIG CSV로 내려받고, 채워 올린 뒤 저장한다. 저장 후 위 2절 후처리가 돈다.

## 6. 최적화 (0.3.0)

- RAG 검색 테이블 목록: 연결당 짧은 TTL 캐시.
- 지명 사전: 해시(내용 동일)면 디스크 쓰기·캐시 무효화를 생략.
- 단계구분도: 식별자 열을 기본 필드에서 후순위로.
